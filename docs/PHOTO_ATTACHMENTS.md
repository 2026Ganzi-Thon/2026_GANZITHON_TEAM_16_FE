# 대화·일기 사진 첨부

`feature/photo-attachments`는 PR #15·#16이 병합된 develop `710c0c5`에서 시작했습니다.
백엔드 PR #23의 계약을 기준으로 구현했습니다.

- 기존 메시지 전송·일기 작성·수정 API에 `payload` JSON 문자열과 반복 `files`를 FormData로 전송합니다. 파일이 없으면 기존 JSON 요청을 유지합니다.
- JPEG·PNG만 선택 가능하며 최대 3장, 파일당 10MiB 제한과 전체 요청 용량을 사전 확인합니다. 실제 이미지 내용 검증은 서버가 수행합니다.
- 선택 사진 미리보기·선택 취소, 사진만 있는 대화 전송, 저장된 대화·일기 사진 표시와 원본 보기 기능을 제공합니다.
- 일기 수정 시 기존 사진 삭제는 `removeAttachmentIds`로 보내며 저장 전까지 서버 사진을 삭제하지 않습니다. 대화 사진은 개별 삭제 API가 없으므로 대화 삭제 시 함께 정리됩니다.
- 전송·저장 실패 시 사진 선택을 유지합니다. 토큰 갱신 후 동일 FormData를 재전송합니다. 화면·계정 변경 시 선택을 정리하며 미리보기 객체 URL을 해제합니다.
- 서명 URL의 5분 유효기간이 끝나 사진 로딩이 실패하면 ‘사진 다시 불러오기’로 상세 API에서 새 주소를 받습니다. URL은 영구 저장하지 않습니다.
- 로그인 없는 미리보기에서는 업로드를 제공하지 않습니다. 사진은 AI 이미지 분석에 사용되지 않습니다.

## 검증

`npm run build`, `npm run check:photo-attachments`, `npm run check:chat-improvements`, `npm run check:monthly-recap`.
브라우저 검사는 모의 API로 multipart 파일 내용·제한·실패 후 유지·401 갱신 후 재전송·일기 사진 삭제·사진만 있는 대화·새로고침 복원을 확인합니다.

2026-11-17 배포 OpenAPI에서도 세 API에 `multipart/form-data`가 포함된 것을 확인했습니다. 실제 S3 업로드·조회·삭제와 운영 인증을 사용하는 최종 검증은 별도입니다. API 존재만으로 운영 저장소 활성화나 권한 설정을 확인할 수는 없습니다.

수동 확인: 일기에 사진 1~3장 첨부 → 저장 → 상세·새로고침 → 원본 보기 → 수정에서 사진 교체·삭제 → 저장. 대화에서는 사진만 전송·보관함 재진입 후 사진 유지도 확인합니다.
