# 월간 회고 및 감정 재확정 안내

## 확인 방법

1. 로그인 후 마음 캘린더를 엽니다.
2. 월별 기록 위의 ‘N월 마음 회고’를 누릅니다. 캘린더를 여는 것만으로 회고 요청을 보내지 않습니다.
3. 회고 팝업에서 이전/다음 달과 월 선택으로 이동합니다. 미래 월은 선택하지 않습니다.
4. 감정 선택 횟수와 AI 회고를 확인합니다. 여러 감정을 고른 일기가 있으므로 횟수의 합은 일기/날짜 수가 아닙니다.
5. 확정 감정이 있는 일기를 수정합니다. 제목만 바꾸면 안내가 없고, 본문을 바꾸면 저장 전 안내가 나타납니다.
6. 저장 성공 후 상세의 재확정 팝업에서 ‘감정 다시 선택하기’를 누릅니다. ‘나중에’를 눌러도 상세의 재선택 버튼은 유지됩니다.

## 회고 API

감정 이름·횟수·막대를 누르면 해당 감정이 확정된 일기 목록이 펼쳐지고, 다시 누르면 접힙니다. 목록은 날짜(YYYY-MM-DD)만 최신순으로 표시하며 날짜를 누르면 일기 상세로 이동합니다. 대표 감정이 아니어도 해당 일기에 함께 선택한 감정이면 포함합니다. 해당 월 목록을 nextCursor 끝까지 조회하고 중복·미확정·다른 월 일기를 제외합니다. 같은 방문에서 감정을 전환할 때 목록은 재사용하고 AI 회고는 다시 요청하지 않습니다. 조회 실패 시 목록만 재시도합니다.

`GET /api/v1/calendar/recap?month=YYYY-MM`은 `month`, `emotionCounts: [{emotionTypeId,count}]`, `concernSummary`를 반환합니다. 이름·색은 `GET /api/v1/emotion-types`로 매핑합니다. 알 수 없는 감정 ID도 횟수를 숨기지 않고 대체 이름을 표시합니다.

- 저장 일기가 없으면 concernSummary는 null입니다.
- AI 실패는 오류이며 빈 월/감정 0회로 바꾸어 표시하지 않습니다.
- 감정 이름 조회 실패 시 회고와 횟수는 유지하고 이름만 재조회합니다.
- 같은 캘린더 방문 중 조회된 월의 결과를 재사용하고, 다른 화면에 갔다 돌아오거나 새로고침하면 새로 조회합니다.
- 월 전환·팝업 닫기에서 요청을 취소하고 늦은 결과는 무시합니다. 계정 변경 시 캐시와 팝업을 정리합니다.
- 개발 StrictMode의 초기 effect 재실행도 취소할 수 있도록 회고 요청 시작을 한 microtask 늦춥니다.

## 감정 초기화 정책과 안내

서버는 본문이 실제 변경될 때 기존 감정과 확정 시각을 초기화합니다. 편집 중에는 저장할 trim된 본문을 원본과 비교하고, 응답에서 실제 초기화가 확인된 뒤에만 재확정 필요 표시를 남깁니다. 실패한 저장, 제목만 변경, 같은 본문에는 성공 안내를 남기지 않습니다.

안내를 유지하는 저장 값은 `mowoo.emotion-reconfirmation.{profileId}`의 일기 ID 목록뿐이며 본문·감정·토큰은 저장하지 않습니다. 계정별로 분리하고 브라우저 세션에서만 유지됩니다. 다른 기기에서 수정한 일기의 초기화 이력은 현재 API만으로 판별할 수 없으므로 그 경우 일반 ‘감정 기록하기’ 버튼을 표시합니다. 감정을 확정하면 안내 ID를 제거합니다.

## 검증

빌드 및 `check:monthly-recap`, `check:diary-emotions`, `check:record-api`, `check:navigation`을 실행합니다. 브라우저 검사는 임시 포트 3100을 공유하므로 순서대로 실행합니다. 모의 API 검증과 실제 운영 AI 성공을 구분합니다.
