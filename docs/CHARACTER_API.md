# 캐릭터 API 연결

`feature/character-api`는 로그인된 사용자의 캐릭터 목록·상세·보유 여부를 실제 HTTP API로 조회합니다. 개발 프록시는 `/api` 요청을 기존 설정대로 `http://localhost:8080`으로 전달합니다.

## 동작

- 목록: `GET /api/v1/characters`의 최상위 `items`를 사용합니다. 고정된 5종 대신 서버가 반환한 항목만 보유/미보유로 나눠 표시합니다.
- 상세: `GET /api/v1/characters/{characterId}`를 별도로 호출합니다. 목록의 `code`와 상세의 `characterCode` 차이를 API 모듈에서 정규화합니다.
- 새 상세 링크는 `?character=<서버 UUID>`를 사용합니다. 기존 `?character=kind` 같은 링크도 서버 목록의 코드로 해석합니다.
- 보유 캐릭터만 선택할 수 있습니다. 선택은 서버 변경 API가 아닌 현재 브라우저 탭의 선호 설정입니다.
- `sessionStorage`의 `mowoo.selectedCharacter`에 `{owner, id}`를 보관합니다. `owner`는 로그인 JWT의 사용자 ID이며 인증 판단에는 사용하지 않습니다. 목록 재조회 후 현재 계정·보유 상태를 다시 확인합니다.
- 인증 상태 변경 시 이전 목록·상세·선택을 비우고, 늦게 도착한 요청은 무시합니다. 로그인하지 않은 미리보기 및 `/design/*`는 기존 로컬 화면을 유지합니다.
- 서버 이미지가 없거나 로딩에 실패하면 기존 캐릭터 그림을 사용합니다. 서버 이름·소개·보유 상태는 그대로 반영합니다.
- 목록/상세의 로딩, 빈 목록, 오류, 재시도, 상세 닫기/Escape 및 키보드 포커스를 처리합니다. 조회 실패 시 예시 데이터를 실제 목록처럼 대신 표시하지 않습니다.

## 직접 확인

1. 백엔드 실행 후 `http://localhost:3000/`에서 실제 카카오 로그인합니다.
2. My 캐릭터 화면에서 서버에 있는 캐릭터와 보유 상태가 표시되는지 확인합니다.
3. 카드를 눌러 상세를 조회하고 보유 캐릭터를 선택합니다.
4. 새로고침 후 선택이 유지되는지 확인합니다. 미보유 캐릭터는 선택할 수 없어야 합니다.
5. 개발자 도구 Network에서 목록·상세 요청과 Bearer 인증 헤더를 확인합니다. 토큰은 공유하지 않습니다.

## 검증

- `npm run build`: TypeScript·배포 빌드.
- `npm run check:character-api`: 모의 HTTP 응답으로 인증 헤더, DTO 변환, 서버 UUID 보관, 새로고침, 미보유 차단, 계정 변경/보유 해제 시 선택 제거, 이미지 대체, 신규 코드, 빈 목록, 오류/재시도, 늦은 상세 응답, 기존 링크, 미리보기, 320/393/1280px 가로 넘침을 확인합니다.
- `npm run check:profile-api`, `npm run check:navigation`: 기존 프로필 API·화면 이동 회귀 검사.

자동 브라우저 검사는 모의 백엔드를 사용합니다. 이번 구현에서 실제 카카오 계정으로 목록·상세의 전체 연결을 직접 수행하지는 않았습니다.

## 후속 범위

채팅은 여전히 기존 모의 API와 임시 캐릭터를 사용합니다. 이번에 보관한 선택 UUID를 실제 채팅 세션 생성에 연결하는 작업과 홈/채팅 헤더의 선택 캐릭터 반영은 후속 채팅 연동에서 진행합니다. 구매 API·전역 선택 저장 API는 추가하지 않았습니다.
